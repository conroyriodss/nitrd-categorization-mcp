One senior NIH program officer, the tool's target user, used the operator
portal on the frozen build (servers at `95e5dea`). There was no protocol, no
task script, no measures and no second participant. What follows is what

## Findings

**F3 (most serious): a not-NITRD card shows only reasons FOR NITRD.**
On 9725122 the card showed p = 0.000 and "Against: none".
* Model `nitrd-parent-v2-ba10594d9581` (sha `92d97bd1...`, sklearn 1.9.1):
  intercept -3.0829. Sigmoid calibration a=-0.991, b=1.864, so on the
  calibrated scale the baseline is about -4.92.
* 9725122 decomposed: intercept -3.08, 182 positive terms +2.42, 449
  negative terms -6.04, logit -6.69, calibrated p 0.000204.
* The participant's reading is partly right. The intercept is large and
  never shown. But on this award the negative terms outweigh the intercept,
  so the call does not rest on the prior alone.
* Root cause, from the code: for a not_nitrd call the portal never calls
  `classifier_explain`. The stored evidence falls back to the parent call's
  `top_features`, which are positive contributions only. So **every**
  not-NITRD card stores `against=[]` and lists terms toward NITRD only.
  This is misleading, not just unhelpful.

**F1: PCA scores are uninterpretable.** "LSDMA 19.33" has no scale or
reference.
* The repeat of 19.33 on 9724345 and 9810625 is **not a cap**. The score is
  a plain sum of discrete term weights, with no cap in the engine.
* The two term lists differ only in `provenance` vs `insights`, and both
  weigh 2.4849 = ln 12, so the sums are equal.
* 5.663 repeats the same way across two different PCAs.
* All recomputed scores equal the stored ones.
* The function word `while` is a matched EHCS term (9730348).

**F2: the rationale is low-signal.** The stored against-lists are dominated
by function words and fragments: `data and`, `through`, `of`, `the`, `in`,
`exploration and`, `an interactive`. The 10388671 explainability work found
the same defect. These are real model contributions, so hiding them is a
presentation choice and must be disclosed.

**F4: the prior-year history sits below the rationale.** The participant
named it the single most useful signal. Its range already covers FY2015 (the
data floor) through FY-1, so there is nothing to extend.

**F5: deciding one card discards unsubmitted input in the others.**
* This is form state lost on the POST/303 re-render, not a stored-state bug.
* Each card is its own form, the page is re-rendered from the tables, and no
  client-side drafts are kept.
* The data agrees: exactly two decision events, and the other three requests
  are still pending and unaltered.

**E1 (positive): error handling under an explicit limit.** FY2021 NEI P30 has
229 records. The selector refused it with "Cohort exceeds 200 projects;
narrow by activity code".
* Submit was disabled, and a bypassing POST is refused again on the server
  (`check_size`).
* No classification ran. The preview calls only `outputs_find_cohort`, and
  Delta history shows no review-table write between 18:40:15Z and 19:19:55Z.
* The time of the refusal was not recorded.

## Fixes and recommendations

The fix list was APPROVED by the owner on 2026-11-08, with the F3 change
below. Nothing is built yet.

* Fixes would land as one display-layer commit after (c) is green, in the
  same window and the same redeploy.
* Boundary: presentation only. No write path, gate, model or new query.
* Anything that needs data not already stored becomes a production
  recommendation.
